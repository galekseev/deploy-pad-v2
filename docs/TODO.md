The engine could verify it — e.g. compile/inspect each pin and validate that every action's `inputs` and `contract`/`module` actually match (constructor arg count/types, return keys for modules, etc.) — and fail fast when a pin drifts from the generation's declared interface.

6. **Plan/preset override for `repository.auth` (git tokens).** Today `repository.auth` lives only in `actions.yaml` and points at a vault entry; the vault is not preset- or chain-aware. Staging vs prod can only differ via which env var is set at runtime (`GH_DEPLOY_TOKEN`), not via the selected preset or plan `secrets:`. Asymmetric with `privateKey`, which is wired per plan/preset. Candidates: plan `secrets:` slot that `repository.auth` names (same rename pattern as PK), or preset-scoped vault lookup. See `actions.md` → Private repos, `global-params.md` → Vault.

See design-decisions.md → Vault redaction, known-chains.md → Credentials & secret handling.
